## 分级(Mivo 统一口径,覆盖规范原文的「严重度」段)

审查机任务书、核对员、Mini 盯梢修复会话与裁决席共用这一份分级(单一来源:Review-PR `mivo/config/severity.md`)。

| 等级 | 定义 | 处理 |
|---|---|---|
| P0 紧急严重事故 | 正在发生或正常使用即可确定触发的大范围灾难性影响,例如严重泄露、批量不可逆数据损坏、系统性不可用,且缺乏有效隔离 | 报 |
| P1 严重缺陷 | 在受支持场景中存在可信、可达的触发路径,导致核心流程失效、严重数据错误或安全/隐私边界被突破 | 报 |
| P2 一般缺陷 | 本 PR 引入或改动范围内已证实的真实问题;影响局部、程度有限,未达到 P1;可能有可接受的绕行办法。除功能缺陷外,还包括下面「P2 必修的三类」 | 报 |
| P3 改进建议 | 没有已证实功能或安全影响的风格、命名、整理、视觉润色,以及下面「P3 不报」列的情况 | 不报 |

P2 必修的三类(问题真实、会误导审查或验收,按 P2 报):

1. 误导性的测试:PR 新增或改动的测试没有真正验证它声称的行为,实现出错时测试也会通过(例如测试替身忽略了参数、用例缺少触发行为的前置步骤、断言恒真)。
2. 自己定的验收没达成:PR 正文、交接文件(`docs/pr/<PR号>/review.md`、`qa.md`)或任务说明里写明的验收标准(覆盖率、用例数、验证项等)实际没达到。
3. 声称做过的验证实际没做:PR 正文或交接文件说做过某项验证、测量或检查,实际没做、做法不同,或写的结论与事实不符。

P3 不报:

- 没有已证实功能或安全影响的风格、命名、整理、视觉润色。
- 生产行为已经正确、PR 也没有声称覆盖的「可以再加测试」或覆盖率建议。
- 不影响结论的措辞、时态、格式问题(例如交接文件里过时但不改变结论的描述)。
- 没有实际收益证据的优化。

判定规则:

- 每条 P0/P1/P2 必须写清:触发条件、错误行为、实际影响、证据。证据不足时先在工作目录里做必要的验证;仍证实不了的不报,在 Rule coverage 里单列「待核实」并写明缺什么证据。不要凭猜测升级,也不要为了少报而降级。
- 多数票、重复意见、工具分数、修复便宜、违反通用规范、单纯缺测试,都**不能单独**构成 P2,也不能单独把问题升到 P1。缺测试或文档不准,只有落在「P2 必修的三类」里才报。
- 规范原文里「记 P1」「按 P1 打回」的具体条款(设计规范、平台或界面证据、PR 描述与 diff 不符、夹带改动、缺必要测试、讨论里的要求未落实等)一律按上表的实际影响重新判:按实际影响判 P0/P1/P2,达到任一报告定义则报;仅 P3 不报。确认的 P2 不得因未达 P1 而舍弃。
- 真实凭证或个人数据进了 diff、恶意代码、越权或数据外发,按实际影响判 P0/P1/P2。
